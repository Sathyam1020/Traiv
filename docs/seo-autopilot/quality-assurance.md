# SEO optimization and quality assurance

## SEO optimization checks (master prompt §10) — all deterministic, no LLM

Title length (advisory, not a hard Google rule), meta description length (advisory),
canonical URL correctness, slug uniqueness (`SELECT 1 FROM post WHERE slug = $1`,
same uniqueness the existing admin post editor already enforces), heading structure
(one `h1`, no level skip — reusing the exact check `audit:seo`/the prior SEO audit
already wrote for the rest of the site), internal/external link validity (every
destination resolves, every internal link points at a real indexable URL), image alt
text presence, Open Graph + Twitter metadata completeness, structured data validity
(JSON-LD parses, has `@context`/`@type`), sitemap eligibility (derived the same way
`featureIsIndexable` already derives it — a published, non-noindex `post` row is
sitemap-eligible by definition, no new predicate needed since the blog's sitemap
inclusion is already unconditional on `status = 'published'`), robots directive
correctness, duplicate-metadata/duplicate-content detection (title/description/slug
uniqueness across all published posts), indexability.

## Structured data (master prompt's list)

`BlogPosting` (reuses `apps/web/src/components/seo-schema.tsx`'s existing component,
unmodified — it already builds `BlogPosting` from real API fields). `Article`,
`BreadcrumbList`, `Organization`, `SoftwareApplication` are the existing site's, not
duplicated per-post. **No FAQ or review markup is generated for autopilot content** —
the master prompt is explicit that markup must match visible page content and must
never promise rich results; FAQ schema specifically only exists today for the
homepage's own real, visible FAQ, and extending it to generated content would require
the draft to genuinely be an FAQ format, verified, not inferred.

## Internal linking

A content graph (`seo_content_opportunities`'s cluster relationships +
`seo_articles`' own stored outbound links) identifies pillar/supporting
relationships and orphan pages. Every recommended link is validated (real,
resolvable, not excessively exact-match anchor text — a deterministic check on
anchor-text diversity across a post's outbound links). **Never rewrites an unrelated
existing page automatically** to add a link back — a suggestion surfaces in the
Optimization Queue (`admin-dashboard.md`) for a human to apply.

## Image strategy

Original diagrams, real product screenshots, and licensed images are supported;
**AI-generated illustrations must be visually distinguishable from product
screenshots and never captioned/alt-texted in a way that implies real product
functionality** — enforced as an explicit check in the originality/claim-ledger pass
(an AI-generated image used to illustrate a claim about product behavior is itself an
unsupported claim). Image generation is optional and budget-gated
(`cost-estimates.md`); no image is generated by default.

## Hard-blocking checks (master prompt §11 — block publication, full stop)

Unevidenced material claim · unverified competitor claim · duplicate of existing
content · search-intent mismatch · missing required metadata · broken internal link ·
incorrect canonical · invalid structured data · misrepresented product functionality ·
fabricated citation · unsafe/unreviewed health claim · editorial-policy violation ·
insufficient original value. Each is a named boolean function in
`quality-gate.ts`, individually unit-testable, combined with `AND` — publication
requires every one to pass, not a score threshold to clear.

## Quality scoring (the subjective half, kept separate from the hard gate)

A weighted rubric (search-intent satisfaction, factual accuracy, originality, depth,
readability, source quality, internal linking, SEO completeness, audience relevance,
editorial consistency) produces a 0–100 score **for the human reviewer's context**,
never as a substitute for the hard-blocking checks above and never as the sole basis
for an automatic pass. Each rubric dimension is labeled as either deterministic
(internal linking, SEO completeness) or LLM-assessed (readability, depth,
editorial consistency) in the admin UI — the same "distinguish deterministic from
subjective" instruction the master prompt gives twice (§6 and §11).

Multiple independent LLM checks are used only where they materially improve
reliability — concretely: the editorial-refinement pass (content-generation.md stage
4) and the quality-scoring pass here use **different system prompts with different
framing** (one is told to improve prose, the other to grade it against a rubric), not
the same prompt invoked twice, directly honoring the master prompt's "avoid repeatedly
asking the same model to grade its own writing."

## Editorial decision

`PASS | REVISE | NEEDS_RESEARCH | NEEDS_EXPERT_REVIEW | REJECT`, each recorded in
`seo_quality_checks` with the explanation that produced it — a human reviewing a
`REJECT` sees exactly which hard-blocking check failed and why, not a bare status.
